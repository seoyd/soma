# BTC prospective Shadow challenge

Historical BTC evidence is consumed development evidence: it has already
informed model development, diagnostics, and the support-gate architecture. It
cannot establish a pristine final result. The next allowed question is a
pre-registered comparison on rows strictly later than the sealed cutoff.

The challenge resolves exactly one support-qualified Shadow-only candidate by
sealed relationships, not by a list index, newest file, training loss, or a
retroactive test choice. Resolution requires validation InSupport, test
InSupport, a selected forensic checkpoint, a frozen encoder digest, a frozen
representation-normalizer digest, a frozen head digest, and a unique artifact
digest. Ambiguous or missing resolution blocks sealing.

The selected candidate is paired with two comparators frozen from the same
historical training boundary: a Linear baseline and a training-prevalence
Constant baseline. Neither is refit as prospective rows arrive. The local
capsule preserves exact IEEE-754 parameter bits and immutable artifact digests;
normal status output never reveals parameter values or probabilities.

The sealed capsule fixes candidate identity, comparator identities, feature and
label policies, support and collapse policies, prediction horizon, primary and
secondary metrics, minimum evidence requirements, verdict rules, abstention
treatment, and one-time opening rules. Its semantic digest excludes paths,
wall-clock values, terminal formatting, and credentials.

The initial challenge is sealed before any future-row inspection or request.
Code and this sanitized policy are committed before the local registry may be
marked pre-registered. The local capsule, evidence vault, and prediction
journal live only in ignored local storage.

Future evidence is stored in an append-only vault separate from development
snapshots and regime packs. A row must be strictly later than the existing
cutoff, finalized, chronologically ordered, canonical, finite, and unique. It
cannot be used for retraining, model selection, threshold work, normalization,
or feature redesign.

For an eligible timestamp, a sealed journal records the candidate/comparator
identities, input digest, support applicability and decision, exact probability
bits, operational outcome, maturity timestamp, and event digest before a label
can mature. Before the one-time opening, ordinary status output shows only
counts and digests; it hides OHLCV, predictions, labels, returns, and per-event
errors.

The primary pre-registered metric is Brier score on support-qualified
prospective events. Frozen Mamba must be compared with both frozen Linear and
frozen Constant; reliability, resolution, uncertainty, guarded AUC,
high-confidence errors, coverage, abstention, support failure, probability
diversity, and collapse are secondary diagnostics. No interim performance
metric is permitted.

Opening is allowed once only after a later explicit authorization and all
pre-registered maturity, support-qualified-event, integrity, and digest checks
pass. Any candidate, comparator, policy, vault, journal, early-label-access,
or duplicate-opening integrity failure permanently invalidates that challenge.

All outcomes remain ShadowOnly. They cannot vote, promote, execute, access an
account, place or cancel orders, or change the Chair, Risk Governor, PaperBroker,
or active three-agent committee.
